# Testing

`cargo xtask ci` is the gate every commit passes: `cargo fmt --check`, `cargo clippy --workspace
--all-targets -D warnings`, `cargo test --workspace`, `cargo xtask layers`, `cargo xtask assets` and
`cargo xtask wasm`. GitHub Actions runs it on Linux and the tests on macOS and Windows
([.github/workflows/ci.yml](../.github/workflows/ci.yml)).

## What every change is tested for

- **Behaviour:** each node's pixels on small synthetic inputs (exact values where the formula is
  known: Merge operations, Grade, Premult), its bbox, and what an unconnected input does.
- **Hostile input:** NaN, infinite and huge knob values, zero scales, empty and gigantic regions,
  malformed scripts and image files, wrong parameter types on every command. The expected outcome is
  an error or a finite image, never a panic.
- **Atomicity:** a failing command leaves the script exactly as it was; a successful one is one undo
  step.
- **Round trips:** `.ncs` save → open gives the same script; PNG (8/16-bit) and EXR (half/float,
  bboxes outside the format) write → read gives the same pixels.
- **End to end:** the demo script built through commands, rendered through Write nodes, saved and
  reopened (`crates/engine/src/tests.rs`); the MCP handshake, tool calls and garbage on stdin
  (`crates/automation`).

## Looking at the result

Pixel changes are checked by eye as well as by numbers: render a frame
(`nukecraft-cli frame demo.ncs --node Write1 --frame 12 --out f.png`) and open it.

## Fidelity against Nuke

Tests pin NukeCraft's behaviour; they don't prove it matches Nuke. That needs an **oracle**: the same
synthetic script rendered by Nuke and by NukeCraft, compared numerically. The harness (M1.6 in the
plan) works like this:

1. A test case is a small script generated by our own code (no Foundry content): e.g. a Ramp through
   a Transform with each filter at fractional offsets.
2. A maintainer with a licensed Nuke renders it headless (`nuke -t render_case.py case.nk out.exr`,
   within the licence's terms) and records **sample values** in `docs/fidelity/<case>.json`.
3. `cargo test` compares NukeCraft's samples with those numbers within stated tolerances.

Only numbers derived from our own synthetic inputs are committed; Nuke renders, screenshots and
scripts written by Nuke stay in `plan/nuke/ref/` (gitignored). [fidelity/README.md](fidelity/README.md)
lists every behaviour still waiting for such a check.
